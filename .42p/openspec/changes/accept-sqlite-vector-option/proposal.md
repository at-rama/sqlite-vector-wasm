# Proposal

## Why

Acquisition, construction and packaging now retain sqlite-vec and offer SQLite-Vector, but complete production/browser acceptance still assumes sqlite-vec. Qualify either selected composition with the same evidence requirements while preserving the working default and its downstream conventions.

## What Changes

- Realize the complete A-acceptance unit for either recorded single-engine composition: clean acquisition/build/package, extracted final-byte browser consumption, independent native query expectations, baseline preservation and exact revision/payload evidence.
- Add explicit recorded source-lock selection to acceptance, retaining existing no-selector sqlite-vec commands and caller-supplied package identity. Bind selected engine, pins and lock identities throughout; reject conflicting or ambiguous selections without fallback.
- Retain all loading, C/OO1, BigInt, FTS5, Worker1/promiser, Float32, binary/Hamming, prerequisite, failure and OPFS restart obligations. Use native SQL for each engine with the existing independently calculated fixtures and no optional quantization dependency.
- Permit only the selected engine's native per-connection column-context initialization after fresh reopen; never recreate/repopulate/repair fixture data or rebuild derived vector data to conceal persistence loss.
- Exercise both retained compositions separately in automatic CI, with isolated fresh state and separately identified artifacts; preserve the required acceptance outcome and existing site-only scope. Manual and downstream exact-payload qualification remain single-composition operations.
- Preserve default report/caller conventions, including Worker1/promiser dimension rows and exact-payload consumers; extend suitable negative controls and contributor documentation.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `browser-acceptance`: retain the full acceptance contract while replacing engine-specific prescriptions with concrete selected-engine qualification, compatible default invocation and isolated evidence for either retained composition.

## Impact

Primary targets are `tools/acceptance/`, `.github/workflows/acceptance.yml`, `docs/acceptance.md` and directly related contributor links. Reuse existing A-build source selection/reference and A-package handoffs/checks; do not change upstream sources, recorded locks, SDK/harness dependencies, build or package semantics. Existing downstream fixtures may need minimal updates to exercise additive identity evidence; their version/channel/preparation/publication policy and implementation remain outside this Change. No general engine adapter, benchmark framework, runtime selector, SQL facade, published API or automatic release switch is introduced.
